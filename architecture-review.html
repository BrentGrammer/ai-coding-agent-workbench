1. One GPU-box contract instead of ~30 scattered declarations

Strong

Files: tools/agents/local_llm.sh infra/aws/lib/workbench-llm-stack.ts bin/workbench infra/aws/ec2/setup-llm.sh infra/digitalocean/droplet/setup-llm.sh infra/aws/ec2/setup-workbench.sh infra/*/llm-idle-stop tools/llm/ollama_inference_proxy.py

Problem: the facts that define the GPU-box seam live in ~10 files with no owner:

  • Model qwen3.8:27b — 5 code locations (+ a Mac variant). bin/workbench:23 admits it: "Defaults must match workbench-llm-stack.ts."
  • Proxy port 11435 — 9 locations. Ollama port 11434 — 7.
  • Hostname agent-llm — 6 files, ~20 occurrences.
  • The S3/Spaces cache key is ${bucket}/${model} in two setup scripts — a mismatched rename silently forks the cache.

Solution: make one deep module — the GPU-box contract: a single generated gpu-box.env (or one source of truth file) emitted by bin/workbench llm and consumed by the launchers, the setup scripts, and idle-stop. CDK/Terraform read the same file when baking user data. The interface shrinks to: source this file, get a working LLM endpoint.

Benefits: locality — "change the model" goes from a ≥5-file, 2-machine edit to a 1-file edit; leverage — every consumer learns one interface instead of re-declaring facts; a drift test (assert all consumers match) becomes possible for the first time. Docs stop rotting because they can be generated from the same file.

2. Cut the GPU-box runtime seam: AWS and DigitalOcean share ~300 pasted lines

Strong

Files: infra/aws/ec2/setup-llm.sh vs infra/digitalocean/droplet/setup-llm.sh · llm-idle-stop{,.service,.timer} ×2 · bin/workbench (DO branch, ~130 inline lines)

Problem: the two provider paths are near-copies. The Ollama override block is character-identical; the .service/.timer units differ by one word; llm-idle-stop duplicates the whole model_is_in_use() heuristic (which embeds the port twice more). Only 4 spots actually diverge: secrets source (SSM vs env file), the destroy fuse, the metadata-service rule, and cache endpoint. The seam between provider lifecycle and serve Ollama + proxy + model cache was never cut — so "add a provider" means copying ~300 lines, and "fix the idle heuristic" must be applied twice.

Solution: one GPU-box runtime module (shared setup-llm-core.sh + shared idle-stop) with a small provider interface: fetch_secret(), arm_destroy_fuse(), cache_endpoint(). AWS and DO become two thin adapters. Two adapters already exist — this is a real seam, not a hypothetical one.

Benefits: locality — the idle heuristic and Ollama config get one home; leverage — a third provider is an adapter, not a copy; testability — the shared runtime can be exercised in a container without cloud credentials.

3. Table-driven agent launchers: 13 copies of one if/else

Strong

Files: all 13 tools/agents/start_*.sh (97–332 lines each) + 11 five-line bin/start-* shims + README table

Problem: every launcher duplicates the existing/new-sandbox if/else with the same step list pasted twice:

if sandboxExists "$SANDBOX_NAME"; then
  allow_network; configure_sandbox_env
  install_pinned_<agent>; copy_config; install_skills   # paste #1
  sbx run "$SANDBOX_NAME"
else
  createWorkbenchSandbox ...; allow_network; upgrade_system_packages
  install_node_lts; configure_sandbox_env
  install_pinned_<agent>; copy_config; install_skills   # paste #2 — same list
  sbx run "$SANDBOX_NAME"
fi

The real per-agent facts are ~5 lines: network hosts, pinned npm package, config path, welcome text. The rest (~500–700 lines total) is structure. A step added to one branch but not the other makes sandbox behavior depend on creation order — a silent bug class. Network hosts are also re-declared per-launcher and in sandbox_bootstrap.sh.

Solution: one deep start-agent module whose interface is a per-agent declaration (a small table: package, hosts, config files, welcome text). The module owns the if/else once. Adding an agent = one declaration row + one shim.

Benefits: locality — the "fresh vs reconnect must match" invariant is enforced by construction, not by discipline; leverage — new agent in ~10 lines; testability — the shared step pipeline can be tested with a fake sbx on PATH.

4. Free the pure functions: ~4,000 lines of shell with one test

Worth exploring

Files: tools/llm/ollama_inference_proxy.py (the good example, 122 ln + tests) · tools/agents/local_llm.sh · bin/workbench · infra/*/llm-idle-stop

Problem: the only testable module in the repo is the Python proxy — and it shows what the rest could look like: pure constants, injected upstream, a fake server on port 0. Meanwhile the highest-churn decisions are trapped in bash mixed with I/O: the jq model-host generators (local_llm.sh:121–199), the Tailscale name→IP query (duplicated, with diverging error contracts — local_llm.sh:59 exits 1, bin/workbench:40 returns empty), the spot-score fallback, the idle-count state machine.

Solution: extract the decision logic at the existing seams: jq filters into standalone .jq files (testable with plain jq -f), the idle state machine into a function taking its inputs as arguments. The interface is the test surface — if a test needs a live Tailscale daemon, the module is the wrong shape.

Benefits: testability without Docker/cloud; locality for the idle heuristic (pairs with candidate 2); drift between the two Tailscale queries becomes a failing test instead of a runtime surprise.

5. Invisible string contracts between modules

Speculative

Files: tools/agents/start_kilo.sh:92 · bin/stop-local-llm:41–46 · tools/agents/local_llm.sh:7–10, 90–95

Problem: several modules couple through strings with no check anywhere:

  • start_kilo.sh copies kilo.jsonc — a file that doesn't exist; if [ -f ] makes the miss silent.
  • stop-local-llm finds processes by grepping launch command text — must stay in sync with how local_llm.sh spawns them.
  • resolve_local_llm silently sources /etc/agent-workbench/workbench.env when present — on such machines --local-model quietly does nothing, and the reason sits 90 lines from the flag parsing.

Solution: mostly resolved as side effects of candidates 1 and 3 (single contract file; pid files written and read by the same module). The remaining piece: make the silent paths loud — fail fast when a referenced config file is missing, and print when the env-file override changes behavior.

Benefits: small, but removes the "why is my flag ignored?" class of bug. Do it opportunistically while deepening, not as its own project.

Top recommendation

Start with Candidate 1 (the GPU-box contract). It is the smallest change with the widest leverage: it touches the exact hot spot the commit history keeps revisiting, it unblocks Candidates 2 and 4 (the shared runtime and the extracted pure functions both need one place to read the model/port/host from), and it can ship in a day with a drift test. Candidate 3 is equally strong but is a bigger, independent project — do it second.

Suggested order: 1 → 2 → 3, folding 5 in as you pass through. Candidate 4 rides along with 2.
